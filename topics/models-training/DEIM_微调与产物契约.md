# DEIM 微调中的配置、前处理与权重产物

DEIMv2 和 EdgeCrafter 的训练结果，不仅由模型与学习率决定。是否真正加载预训练权重、是否使用正确归一化、数据划分是否泄漏，以及验证使用的是普通权重还是 EMA，都可能改变最终指标。

归档 DEIMv2 微调曾得到 AP@0.5:0.95 40.63%，较从头训练高约 2.18 个百分点；另一组后期比较又暴露了微调参数遗漏和前处理差异。这些结果共同说明，比较模型之前应先核验训练契约。

# 一、微调需要证据

训练命令中的权重路径不保证权重真正加载。某些入口区分 resume 与 tuning，遗漏对应参数会进入从头训练。启动日志应保存已加载、缺失和形状不匹配的参数，以及分类头是否重新初始化。

| 模式 | 权重 | 优化器与调度器 |
| --- | --- | --- |
| 从头训练 | 随机初始化或明确基础初始化 | 新建 |
| 微调 | 预训练参数，头按类别适配 | 通常新建 |
| 恢复训练 | 完整训练 checkpoint | 恢复 |

配置文件还需校验数值类型。某些 YAML 解析器把 3e-4 读成字符串，导致优化器后续失败；生成器应写明确浮点值并做 schema 校验。

# 二、前处理随骨干变化

归档 ViT/DINOv3 系列使用 ImageNet Normalize，HGNetv2 轻量系列的路径不同。模型规模名称不足以决定前处理，应同时核对配置与实际 checkpoint 结构。

训练、验证、ONNX 参考和平台校准复用同一份数值规则。添加归一化不一定是改善，重复执行或使用另一模型规则，反而改变输入分布。

# 三、训练速度与验证速度

缓存图片可以减少重复解码，但总时长下降不等于 GPU kernel 提速。记录训练迭代、数据加载、验证和保存分别耗时；不带这些分项，模型间“快几倍”很难解释。

早停监控应使用任务指标，进入无增强阶段后再按新的耐心值判断。训练 loss 仍下降但 AP 停滞时，不必继续堆积 epoch。低置信度阈值只改变推理选择，也不能代替训练收敛。

# 四、权重产物

归档完整 checkpoint 约 156 MB，其中包含普通模型、EMA 和 AdamW 等状态。只保存评测实际采用的 EMA 权重后约 39 MB，可用于推理和再微调，却无法等价恢复原训练。

```text
resume.pth       完整模型＋优化器＋调度器＋训练进度
inference.pth    选定的模型权重
model.onnx      固定推理接口
manifest.json   类别、前处理、版本与指标
```

明确拒绝用 inference 权重执行 resume，能够防止“恢复成功但状态不同”的隐性问题。

# 五、一些反思

同一 AP 数字只有在数据、标注口径、前处理和训练预算一致时才适合比较。标注从局部目标改为整个人、拆分方式改变或难例增加，都会让旧数字失去基线意义。

训练工程最有价值的改进，往往是让“实际做了什么”可核验。权重加载报告、配置类型检查和产物区分，比增加更多可选参数更能保护实验可信度。
