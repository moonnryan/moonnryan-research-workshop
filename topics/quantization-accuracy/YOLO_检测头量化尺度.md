# YOLO 检测头的输出范围与量化尺度

YOLO 的检测头常把框坐标和类别分数拼成一个输出。对浮点推理，这只是接口组织；对使用单一输出尺度的整数后端，数值范围差异可能直接破坏类别分数。模型可以正常运行、输出 shape 也正确，却在后处理中没有任何有效框。

归档 INT8 测试出现过这种情况：boxes 的范围接近输入像素尺寸，scores 位于 0–1；拼接输出的 scale 约为 2.511，而拆分后 scores 的 scale 约为 0.003665。这个变化解释了为什么“检测全空”不一定来自阈值设置。

# 一、输出拼接的代价

仿射量化可以写为：

$$
q=\operatorname{clip}\!\left(\operatorname{round}(x/s)+z\right),\qquad
\hat{x}=s(q-z)
$$

当 $s$ 大于分数差异时，多个不同分数会映射到同一整数值。例如 $s=2.511$、$z=0$，正分数 0.9 的量化值也会接近 0。调整阈值无法恢复已经丢失的分辨率。

| 分支 | 典型范围 | 需求 |
| --- | --- | --- |
| boxes | 像素坐标或距离 | 覆盖较大动态范围 |
| scores | 0–1 | 保留阈值附近的小差异 |
| 关键点 | 坐标与可见性 | 按任务重新定义 |

具体是否发生共享尺度，要检查实际量化参数。不能仅凭输出拼接就断言所有后端都存在同样问题。

# 二、让量化边界匹配语义

对确认采用 `[B,4+nc,N]` 的 detect 图，在输出边界显式拆分 boxes 与 scores：

```python
# 适用于已核实的 [B, 4+nc, N] 输出；
# pose、嵌入 NMS 或其他排列需重新定义。
boxes = prediction[:, :4, :]
scores = prediction[:, 4:, :]
return boxes, scores
```

切分改变输出接口，不改变分支数学含义。后处理同步接收两个张量，并记录各自量化参数；不能把已反量化的结果再套一次 scale。若后端仍在分支之前共用范围，单纯修改输出声明可能无效，需要确认切分位置和编译融合。

# 三、数值与任务验收

归档例中，拆分后的最高分从浮点参考约 0.915 对应到量化约 0.935，恢复了可用分数。但单图成功只证明问题被缓解，发布仍需验证 AP、阈值附近样本、负例误报与坐标还原。

阈值、TopK、NMS 会放大微小分数差异。因此除了整体余弦，还应比较有效框数量、类别和匹配 IoU。对全空输出，先打印未过滤分数，比不断调低阈值更有信息。

# 四、一些反思

接口设计参与了量化行为。把不同语义的数据拼在一起，可能让后端看见一个不适合共享范围的张量；输出拆分把模型语义转成编译器可利用的边界。

量化检查应覆盖输出。若最终分数已经被量化范围吞没，再精细的后处理都无法恢复模型判断。
