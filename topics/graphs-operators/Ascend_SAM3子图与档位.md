# Ascend SAM3 子图拆分与动态档位

SAM3 的图像编码、文本编码和 grounding decoder 具有不同的输入变化维度。把它们拆成独立 ONNX/OM，可以分别验证图像数、概念数与缓存复用，但某个子图支持动态档位，不代表完整模型已经动态化。

归档材料中 grounding decoder 的多图、多概念组合可运行，image encoder 仍受目标 ATC/runtime 的动态输入限制。部署边界应按子图分别描述。

# 一、拆分与接口

| 子图 | 主要变化 | 验收 |
| --- | --- | --- |
| image encoder | 图像数与尺寸 | 特征 shape、位置编码 |
| text encoder | prompt 数 | 文本 token 与特征 |
| grounding decoder | 图像与概念组合 | 维度配对与输出 |
| 后处理 | 阈值与坐标 | 原图映射 |

静态档位可以选择 1/2/4 图等实际需求，而不必把所有维度都变成动态。动态参数必须同时得到导出图、ATC 和板端 runtime 支持，仅设置编译选项不能生成不存在的动态能力。

# 二、吞吐的分母

设图像数为 $I$，概念数为 $K$。decoder 一次处理 $I\times K$ 个图像概念组合，工具默认吞吐可能只使用图像 batch 作为分母：

$$
R_{\mathrm{pairs}}=\frac{IK}{T_{\mathrm{decoder}}}
$$

归档 1×1 约 25.63 ms、4×4 约 306.32 ms，对应约 39.0 与 52.2 pairs/s。后者的 batch 延迟更大，单位组合吞吐稍高；不能把它解释为完整 SAM3 每秒处理 52 张新图。

# 三、缓存与端到端成本

复用图像特征可以减少 image encoder 重复执行，复用概念特征也可减少文本编码。缓存键至少包括媒体内容、前处理、模型版本和 prompt，不能只按文件名保存。

最终延迟包含编码、decoder、传输与后处理。对每张图只查询一次的负载，编码缓存收益有限；对同图多概念则更有价值。需要用真实查询模式评估。

# 四、档位选择与模型服务

为实际负载选择有限档位，并在入口把请求映射到适合的 profile。若需要 padding，图像与文本 mask 必须同步，不能把填充概念的输出当成真实结果。

图像编码结果与原图尺寸、位置编码和前处理共同绑定。服务缓存应明确容量和淘汰策略；同图多概念复用可以减少编码，但长期保存所有输入会占满宿主或设备内存。

公开接口以图像和概念表达任务，内部档位作为实现细节。请求超出已验证组合时返回明确错误或执行受控分批，并校验分批后输出顺序及时间成本。这样后续扩充档位时不必改变用户的数据格式。

# 五、一些反思

动态输入适合表达实际变化，静态档位适合控制编译与验收复杂度。二者可以组合，关键是把子图支持范围写清楚。

工具的吞吐数字必须知道分母。图像数、概念数和组合数对应不同工作量，先统一口径才能比较部署方案。
